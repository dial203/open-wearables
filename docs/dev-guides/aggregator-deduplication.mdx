## Why this exists

Anyone running several brands ends up with both kinds of connection at once:

- **Direct** — the maker's own API. Garmin, Oura, Whoop, Polar, Withings, Fitbit.
- **Aggregator** — Apple Health, Google Health, Health Connect, Samsung Health,
  Strava. Needed because some devices have no other route: an Apple Watch, an
  app with no public API, a sensor that only writes into HealthKit.

An aggregator re-exposes everything on the phone, including the brands you
already read directly. The Oura ring you connected to Oura's API arrives a
second time as "Oura" inside Apple Health, the Garmin arrives again as
"Connect", and every listing, chart and export shows each device twice.

**The rule:** for the span the direct route actually covers, the aggregator's
copy of that same brand is left out of reads.

## What it does not hide

The rule is deliberately narrow, because hiding a device's only copy of a day
is far worse than showing it twice. It never hides:

A brand with no direct integration at all — Zepp, Eight Sleep, a third-party
HealthKit writer — is never affected, and neither is an aggregator's own data
(an Apple Watch inside Apple Health is first-party, not a relay).

## Nothing is deleted

Ingest is unchanged: relayed rows keep being written exactly as before. The rule
filters reads only, and every read takes `include_redundant_relays=true` to get
the relayed copies back — for checking the direct route's completeness, or for
comparing the two paths against each other, which stays a supported analysis.

```bash
# Default: the redundant copy is left out
GET /api/v1/users/{user_id}/timeseries?types=heart_rate&start_time=...&end_time=...

# Everything, both routes
GET /api/v1/users/{user_id}/timeseries?types=heart_rate&include_redundant_relays=true&start_time=...&end_time=...
```

Applies to the time series and event (workout, sleep, menstrual cycle)
endpoints. A read that names a single `data_source_id` is never filtered:
asking for a source by id is asking for that source.

## Nothing disappears silently

When the rule leaves something out, the response says so in
`metadata.relay_dedup`:

```json
{
  "metadata": {
    "relay_dedup": {
      "applied": true,
      "hidden": [
        {
          "data_source_id": "8f14e45f-ceea-467a-9d2f-1b2c3d4e5f60",
          "provider": "apple",
          "brand": "Oura",
          "direct_provider": "oura",
          "covered_from": "2026-03-01T00:00:12Z",
          "covered_until": "2026-06-01T11:58:40Z",
          "reason": "covered_by_direct"
        }
      ]
    }
  }
}
```

`GET /api/v1/users/{user_id}/data-sources` carries the same classification per
source: `ingestion_route` (`direct` or `aggregator`), `redundant_relay`, the
`direct_provider` that made it redundant, and the `relay_visibility` override.

## Overriding it for one source

```bash
PATCH /api/v1/users/{user_id}/data-sources/{data_source_id}/relay-visibility
{ "relay_visibility": "always" }
```

| Value | Meaning |
| --- | --- |
| `auto` | Follow the rule. The default, and the only value the system ever sets itself. |
| `always` | Keep this source in every read, whatever the rule says. |
| `never` | Hide it outright, even where no direct source covers the span. |

Only the override is stored. Redundancy itself is recomputed per read, because
it depends on what the direct route has actually delivered — and that changes
when a token expires, a backfill lands, or an account is revoked. A stored flag
would go on asserting an answer that had stopped being true.

## Limits worth knowing

- **Coverage is a span, not a calendar.** Within the requested window the rule
  uses the first and last direct sample per brand and series type. A gap
  *inside* that span — the direct API missing a Tuesday it should have had —
  keeps the relayed copy hidden for the Tuesday too. Re-read with
  `include_redundant_relays=true` when completeness is the question.
- **The unit is a brand, not a device.** With two Garmins both connected
  directly, a relayed Garmin stream that names no device is hidden across the
  span even if it came from the unit that syncs less often. Set
  `relay_visibility: "always"` on that source if it matters.
- **A read naming no series type gets one coarser span per brand**, since
  measuring coverage for every type would cost a query per type. Every
  timeseries read in practice names its types.
